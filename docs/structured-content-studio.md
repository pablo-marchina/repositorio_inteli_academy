# Structured Content Studio

## Objective

The Content Studio optimizes for three properties at the same time:

1. high visual quality;
2. fidelity to the real Inteli Academy identity;
3. editability after AI generation.

The canonical artifact is therefore **not a generated bitmap**. The AI produces editorial content plus a structured scene description. Figma remains the executable visual source of truth for social design, and Remotion consumes the same structured video timeline for motion preview.

## Visual precedence

1. real Instagram posts explicitly selected by the user;
2. synchronized historical `@inteli.academy` behavior;
3. Figma `Social Media` as the principal executable visual source for social formats;
4. the other audited ID Academy pages as complementary identity context;
5. optional article evidence and user context for factual/message constraints.

## Why the Figma strategy changed

A live audit of the current `Social Media` page found many editable production frames but only a small number of formal reusable components. Rebuilding the visual language from hardcoded rectangles and typography would therefore discard valuable identity information.

The bridge now uses **editable frame inheritance**:

- find a compatible real frame on `Social Media`;
- clone the complete Figma frame;
- preserve vectors, masks, images, effects, groups and existing typography;
- identify semantic content nodes;
- replace only the requested semantic roles;
- keep the rest of the template intact.

If a new AI version is created from a version that was already edited manually in Figma, the new scene stores the previous Figma frame IDs as its base. The bridge clones that human-edited frame and applies only the roles that changed. This is the round-trip preservation mechanism.

## Semantic Figma bindings

Editable output nodes are tagged through their Figma layer names:

- `AI::headline | ...`
- `AI::eyebrow | ...`
- `AI::body | ...`
- `AI::stat | ...`
- `AI::statLabel | ...`
- `AI::bullets | ...`
- `AI::media | ...`
- `AI::logo | ...`
- `AI::pagination | ...`

The backend can read these nodes through the Figma REST API before a later revision. Human text edits therefore become part of the next AI input instead of being silently overwritten.

## Scene Graph

Each generated version can carry an `artifact` with schema version 2. The Scene Graph records:

- semantic role;
- element kind;
- editability;
- whether the element is protected by the brand;
- Figma source page;
- template hints;
- original Figma base frame ID when applicable;
- selected Figma template node ID after import;
- final Figma output frame ID;
- roles changed by the revision;
- Drive asset bindings.

This structure is stored inside the existing `content_versions.payload` JSONB, so no database migration is required.

## Brand quality gates

Two complementary checks exist.

### Structural brand linter

Runs when the structured artifact is compiled and checks that:

- `Social Media` is the design source;
- elements remain structured/editable;
- density stays inside mobile-safe limits;
- protected brand elements come from the Figma template instead of being regenerated by the AI.

### Visual critic

After the Figma plugin imports the version, the backend can render both the selected source template and the generated output and compare them multimodally. The critic evaluates visual hierarchy, composition, proportions, perceived typography, graphics, logo treatment, whitespace, contrast and overall fidelity.

A critic outage does not delete or invalidate an otherwise successful editable Figma import; the result remains available for human review.

## Video architecture

Reels use the same structured artifact instead of a separate visual system.

The video timeline records independent tracks such as:

- footage;
- brand graphics;
- eyebrow;
- headline;
- body;
- logo;
- future voice/music/SFX tracks.

Remotion powers the temporal preview. The currently generated default timeline is 1080×1920 at 30 fps and can be revised structurally.

The motion endpoint accepts natural-language timing requests for an existing structured Reel version. Examples include moving the headline later, changing the total duration or changing when body copy appears. The request updates track timings instead of flattening the project.

## Editor export

For a structured Reel version the platform exposes:

- **OTIO** (`format=otio`) for editorial timeline interchange;
- **Academy editor manifest** (`format=manifest`) containing the complete Scene Graph, track metadata, editable text intent, Drive assets, brand reports and Figma bindings.

OTIO is used for timeline structure, timing, track separation and media references. It should not be treated as a guarantee that every editor will reconstruct every motion-graphics effect as the same native object. Editor-specific adapters can consume the Academy manifest to create native titles/graphics for Premiere, After Effects, Resolve or Final Cut while preserving the same canonical structure.

## Publishing invariant

For single posts, carousels and Stories, publishing always re-renders the **current Figma frame IDs at approval time**. Manual changes in Figma are therefore reflected in the published image.

For Reels, the structured Remotion timeline and editor exports are now available for review/editing. The current Instagram publishing path still uses the explicitly selected Drive footage until a final rendered motion artifact has its own explicit approval state; the system must not silently publish an unreviewed generated video.

## User flow

1. choose post, carousel, Story or Reel;
2. optionally select articles, user context, multiple real Instagram reference posts and Drive media;
3. generate a structured version;
4. inspect structural brand fidelity;
5. request editorial/visual revisions;
6. send the chosen version to Figma;
7. the plugin clones a real editable `Social Media` frame or the previous human-edited base;
8. edit freely in Figma;
9. generate another version without discarding semantic human edits;
10. for Reel, preview with Remotion and export OTIO/manifest for an external editor;
11. approve the reviewed final state;
12. publish.

## Legacy compatibility

Versions created before artifact schema v2 remain readable. When a legacy Studio payload is queued for Figma, the backend can compile the structured artifact at queue time, so existing projects do not require a migration.
